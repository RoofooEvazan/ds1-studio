1Getting started ↑ Contents

DS1 Studio opens the map presets (DS1 files) of classic Diablo II and your mod straight from the game's files, draws them the way the game does, and lets you edit their tiles, objects, the game's level tables, the automap and the tile libraries (DT1 files) themselves. See the Glossary for any term you don't know.

1.1Installing

Download the latest version from the Releases page on GitHub:

SystemFileNotes
Windows 10/11…_x64-setup.exeRecommended. Installs for your user and updates itself.
…_x64_en-US.msiFor managed installs.
Linux….AppImageRuns on most distributions; make it executable and double-click. Updates itself.
….deb / ….rpmDebian/Ubuntu, Fedora/openSUSE packages.
Note The Windows installer isn't code-signed yet, so Windows may say “Windows protected your PC”. Click More info → Run anyway.

1.2First start: choosing your folders

The first time it runs, DS1 Studio asks for two folders:

  • Diablo II — the folder with d2data.mpq, d2exp.mpq and patch_d2.mpq. It is only ever read.
  • Mod folder (optional) — your mod's folder with its data/ tree. This is where everything you save goes (see Saving). Tick Also read the mod folder's own .mpq files if your mod ships its data in MPQs.

On Linux, point it at the Diablo II folder inside your Wine prefix. You can change the folders later with Home → File → Folders… Nothing else is needed: object names and sprites come from the game's own files, and special tiles get DS1 Studio's own markers.

Quick start: your first edits

Ten minutes from opening DS1 Studio to a map in game. Each step links to the section that explains it fully. (The pictures below move in the HTML version of this manual; the PDF shows their first frame.)

  1. Open a map. Type part of its name in the filter above the file list on the left and click it; F fits the whole map in view. Scroll to zoom, right-drag or the arrow keys to move around. More…
  2. Paint. Press B (Paint), click a tile in the Tiles panel on the right, and drag over the map. Ctrl+Z undoes. The Active layer (Home tab) is the layer you paint on; Shift+scroll moves the tile to the layer in front or behind. More…
  3. Select, copy and move. Press V and drag to select; Ctrl+C copies and the copy follows the mouse — click to paste. Double-click a tile to select every copy of it. More…
  4. Place objects and NPCs. Press O, pick one in the gallery on the right, and click the map. More…
  5. Save. Ctrl+S writes the map into your mod folder (the original is kept as .bak). More…
  6. Put it in the game. Game → Add to game writes the rows the game needs (Levels, LvlPrest, LvlTypes), then Diagnostics → Compatibility checks everything and offers one-click fixes. More…

Set things up the way you like in Home → Preferences… (1.5): saving when you switch maps, the Act 0 colours, paste mode, what a map opens with, scroll speeds and New map defaults.

1.3A tour of the window

  1. 1Tabs: Home (files and editing), View (how the map is shown, and the view modes), Map (the map and its tile libraries), Game (the game's tables, and checks) and Help switch the ribbon below.
  2. 2Ribbon: the commands, in labelled groups (File, Edit, Tools, Paint / erase, Layer on Home). Hover any button for what it does and its shortcut.
  3. 3Suggest a feature and the open map's name and path. A dot after the name means unsaved changes.
  4. 4Presets list: every DS1 in the game and your mod. Type in the box to filter (see Opening a map). The button left of its title folds it away to a thin strip for more map room; click the strip to bring it back.
  5. 5Map view: the map as the game draws it (see Viewing maps).
  6. 6Minimap: the whole map; click it to move there (2.2).
  7. 7Side panels: Tiles/Presets, Selection, Cell, History, Layers, Map… (they change with the tool). In a view mode (Walkability, Automap, Level light, Roof hiding) they make way for that mode's own panel (see View modes).
  8. 8Status bar: the data sources, the tool and layer, the cell under the mouse, zoom, size and act.

1.4Opening a map

  1. Type part of the path in the box above the presets list, e.g. act1/town or arcane.
  2. Click a map in the list. It opens with the tile libraries the game would use for it (from LvlPrest.txt → Levels.txt → LvlTypes.txt) and the right act palette.
  3. Press F to fit the whole map in the view.

You can also reopen a recent map (1.7), create a new one (3.9) or import one (7.1).

1.5Saving, and where files go

Save (Ctrl+S) writes the map into your mod folder, under the same path it has in the game. If a file is replaced, the original is kept next to it as <name>.bak (only the first time, so the true original survives). Save as… saves under a new path. Your Diablo II install is never written to.

Everything else DS1 Studio writes — edited DT1s, .txt tables, presets — also goes into the mod folder with the same .bak safety. See Safety and troubleshooting.

Switching and closing maps. Opening another map saves the one you're leaving first (Home → Preferences… turns this off; then a map with unsaved changes asks whether to save or discard them). Esc with nothing selected asks to close the map: Save and close, Discard and close or Cancel.

Preferences (Home → Preferences…), remembered on this computer:

  • Maps and saving: save before opening another map; how often unsaved work is autosaved for recovery (0 = off); how many recent maps to keep; run the Compatibility check after saving and/or after Add to game (it opens only when it finds problems).
  • Colours: show maps in the Act 0 colours; mark colours that change between acts in magenta (see below).
  • Editing: paste onto existing tiles (stack) by default, with Alt then replacing; ask before deleting several objects at once or a preset.
  • What a map opens with: the walkable area box (also View → Walkable area), grid, minimap, and object names on the map.
  • Mouse and keyboard: mouse-wheel zoom speed, arrow-key scrolling speed, and whether Shift+wheel steps through layers (Alt+wheel zooms) or zooms (Alt+wheel steps through layers).
  • New map starts with: size, act, layers and folder.

Colours. Maps are shown in the Act 0 colours by default (Preferences: Show maps in the Act 0 colours): the colours that look the same in every act, with the ones that change between acts shown as they look in the map's own act, so nothing turns magenta. Tick Mark colours that change between acts in magenta to see which pixels still need Make act-safe. A palette picked in View → Colours for a map is kept for that map.

1.6Autosave and recovery

While a map has unsaved changes, DS1 Studio keeps a copy of it every 20 seconds in its own storage (never in your game or mod folders). If the app crashes or is closed without saving:

  • the start page lists Unsaved work kept from an earlier session, and
  • opening that map offers Restore (the autosaved version opens, unsaved until you save) or Discard them.

Saving, or undoing back to the saved state, removes the kept copy.

1.7Recent maps

Home → File → Recent ▾ lists the maps you opened last; the start page lists them too. Tick Reopen the last map on start to have your last map open automatically.

1.8Updates

The app checks GitHub once a day and tells you when a new version is out. Help → Check for updates downloads and installs it and restarts DS1 Studio. Help → About shows the version and build.

2Viewing maps ↑ Contents

2.1Moving around and zooming

ZoomMouse wheel (zooms around the mouse)
PanArrow keys (Shift = faster), Space + drag, or drag with the middle or right mouse button
Fit the whole mapF
Jump anywhereClick or drag on the minimap

At 100% you see exactly the game's pixels; zoomed out, tiles are properly downscaled instead of turning grainy.

2.2The minimap

The bottom-left corner shows the whole map with the visible area outlined. Click or drag on it to move the view there. Toggle it with K or View → Show → Minimap.

2.3Layers: showing and hiding

A map has up to 2 floor layers, 4 wall layers (walls, roofs, lower walls, special tiles, trees and objects that are tiles), shadows, and optionally a tag layer.

The Layers panel shows or hides each one and says how many cells it uses. The number keys toggle them too: 1/2 floors, 3–6 walls, 7 shadows, 8 roofs, 9 lower walls, 0 special tiles.

Hiding a layer only affects the view. To edit a layer, make it the active layer (3.1).

2.4View modes, grid, rooms

Walkable area. The box at the bottom right of the map shows how much of the map a player can stand on, in tiles² (the walkable sub-tiles of the Walkability view, 25 to a tile), updated as you edit. It is grey below 3,300, green from 3,300 blending to orange at 3,800, orange blending to red by 4,300, and redder above that.

Walkable and Spawns. Two colour overviews in the Show group (also in the Layers panel), one at a time, with a legend at the top right of the map. Walkable colours every floored sub-tile green where players can walk, yellow where only monsters can (flag 0x08) and red where nothing can (flag 0x01 on any floor or wall tile there, hidden tiles included, or the cell's unwalkable bit). As in game, a cell without a floor blocks nothing unless a tile there does (with LvlPrest FillBlanks, the hidden blank floor 30 the game puts there): void players can walk into from the floor is magenta, and the floor edge where they walk off is outlined orange (the compatibility check lists these edges too). Spawns colours where the game can place random monsters green, and the rest by the reason it can't: blocked, a node region (its seed's first floor tile is hidden or main index 30), a room with a level warp, or a level that spawns none at all (LvlPrest Populate 0, Levels.txt MonDen 0 or no monsters listed), plus the map's last row and column, which belong to no game room. Objects and monsters already there block spots too; those aren't shown.

View modes. The View tab's Mode group switches what the right-hand panel is for, one mode at a time: Tiles (editing: the Tiles, Cell, History, Layers and Map panels), Walkability (W), Automap (A), Level light (Shift+L) and Roof hiding (H). Each mode draws its view on the map and replaces the side panels with only its own options; Done at the top of the panel (or the mode's button or key again) goes back to Tiles. Tab steps through the views in turn (Tiles, Walkability, Automap, Level light, Roof hiding) and Shift+Tab goes back. The Show group's overlays (grid, rooms, minimap, sprites, markers, As if inside) are not modes: they work in any mode.

Automap (A) draws the in-game automap over the map, as players will see it (see The automap).

Level light (View → Level light, Shift+L) draws the map as brightly and in the colour the game lights its level: Levels.txt's Intensity (1-255) and Red/Green/Blue; 0 means the act's own daylight, as towns and outdoor levels use. The Map panel and the Level light panel show and change them: the Intensity slider or a number, the colour, and Apply to Levels.txt; the values in Levels.txt are shown underneath, Reset goes back to them, and the map previews every change. Moving a daylight level (Intensity 0, which usually stores colour 0,0,0) to a fixed light starts from white light, since 0,0,0 would be black. In game the player's own light radius also brightens the area around them.

2.5Game view

Game view (Z) zooms to exactly what the character sees in game, centred on the selection, and shades everything else. Pick the screen size next to it: 640×480, 800×600, PD2's widescreen sizes, or a custom size.

2.6Objects, sprites and animation

Objects and NPCs are drawn with their real sprites, animated at the game's speeds, with fire, glows, magic and fog blended as in game. Sprites (N) toggles the sprites, M the object markers, P the NPC paths. Animated floor tiles (water, lava) animate too. See Objects and NPCs for editing them.

2.7Special tiles

Special tiles are invisible in game: they mark warps, where players arrive in town or on a map, the corpse and town-portal spots. DS1 Studio draws a labelled marker on each, e.g. Town entry 1, Map entry, Corpse location. Warps show where they lead, e.g. Warp · link 1 → Catacombs Level 1; see Warps: connecting maps.

Placing them: right-click a cell and choose Place a special tile here: Map entry, Town entry 1 and 2, Corpse location, Town portal location, or a warp (Vis 0–7). It goes on the first wall layer free at that cell (a new wall layer if all are taken). They are also in the Tiles panel with a wall layer active: the Special filter lists them (from builtin/special tiles, DS1 Studio's own stand-ins, since the game draws nothing for them).

Where map portals arrive A player who comes in without a warp (through a map item's portal) is put, by the game, at a waypoint if the level has one, else in a room with a warp tile, else in the room at the centre of the level, on the nearest free ground there; if that room has no floor the game stops. The Map entry tile doesn't change this. So place a waypoint where players should arrive: the map can then stay any size, with its tiles anywhere. The Compatibility check asks for one (Place a waypoint puts it on the cursor), and Add to game warns at the top when the centre is empty, with Place a waypoint and, as an alternative, Crop the map to what's painted. For arrivals the waypoint only has to be there; whether players can also travel with it depends on the level's waypoint slot (Levels.txt Waypoint; 255 = none). New maps start with the game's special-tile library, act1/barracks/warp.dt1, as maps usually load.

Roof hiding

When a player walks into a building, the game fades its roof. This is set by a hide area: two special tiles (main index 8–29) at opposite corners of the inside, whose sub index is the main index of the tiles that fade. Every wall-layer tile with that number in the area, plus one cell around it, fades while the player stands inside. The trigger is the rectangle, grown or shrunk toward the south and east by LvlPrest's PopPad (in sub-tiles; the game's houses use −4). The game ignores hide areas unless LvlPrest's Pops counts them.

  • View → Roof hiding (H) fills the area the player must stand in, outlines the area whose tiles can fade, and marks those tiles.
  • View → Show → As if inside (Shift+H) hides those tiles, as the game shows the map while a player is inside.
  • Map → Roof hiding… (or Change roof hiding… in the Roof hiding panel): select the inside of a building (the floor players walk on), open it, tick what should fade (roofs are ticked for you), and click Add hide area. DS1 Studio places the corner markers and sets Pops/PopPad. The dialog also lists and removes existing areas.
  • Map → Wall hiding… is the same with the walls ticked instead of the roof: the walls in front of a room (usually its south and east walls) fade while a player is inside, so they don't block the view. It uses the same hide areas and the same limits (at most 4 kinds of tile per area).
  • The Compatibility check reports hide areas the game would ignore (Pops 0 or too small) and markers it would merge into one rectangle, such as the same number used for two buildings.

2.8Overlapping (stacked) tiles

Trees over trees, a wall over a floor: when several tiles overlap under the mouse, hold Shift and turn the mouse wheel to step through them one at a time. Only that tile's layer is selected, so Copy, Cut and Delete leave the others alone; Esc selects all layers again. Clicking a tile also shows it in its DT1 in the Tiles panel.

3Editing tiles ↑ Contents

3.1The tools

ToolKeyWhat it does
SelectVClick a cell to inspect and edit it in the Cell panel; drag to select an area; Shift+click or Shift+drag adds to it (3.4).
PaintBPaints the tile chosen in the Tiles panel on the active layer.
EraseEClears cells on the active layer.
PickIClick a tile on the map to paint with it.
ObjectsOSelect, move, add and delete objects and NPCs (chapter 4). Shift+O switches between tile and object editing.

The Active layer list chooses which layer Paint, Erase, Fill and Clear work on. Floors take floor tiles; wall layers take walls, roofs, lower walls, trees, objects and special tiles.

3.2The Tiles panel

The Tiles panel shows every tile the map's libraries provide for the active layer.

  • Click a tile to paint with it (switches to Paint).
  • Ctrl+click more tiles to paint a random mix: each painted cell gets one of them. clear mix in the header goes back to one tile.
  • Right-click a tile to pin it (★) to the strip at the top; Recent lists what you used last. Both are remembered per tile set (level type).
  • The drop-down shows one DT1 at a time; on wall layers the chips filter walls, objects, roofs, lower walls and special tiles; the box finds a tile by main/sub number.
  • Ctrl+wheel over the panel zooms the thumbnails.
  • Rest the pointer on a tile for an enlarged view of it beside the panel (crisp pixels, up to 3×) with its size, variants, source DT1 and what clicking does. Thumbnails and this view are shown a little brighter than the game's dark palettes; the map and the files are unchanged.

3.3Painting: freehand, rectangle, fill

Paint and Erase work in three ways, chosen in the Paint / erase group:

ModeKeyHow
FreehandBPaints the cells the mouse passes over.
RectangleUDrag a rectangle; it's all painted (or erased) when you let go.
Fill areaLClick a cell: the connected area of the same tile is filled. If you click inside a selection, the fill stays inside it.
Tip Every stroke, rectangle or fill is one step to undo (3.6).

3.4Selecting, copying and moving

With Select (V), drag over the map to select cells, or press Ctrl+A for the whole map. Hold Shift to add to the selection: Shift+click adds one cell, Shift+drag adds a rectangle, so you can select any shape (an L-shaped room, a winding path). Shift+click on a cell that is already selected takes it out again (and Shift+drag starting on one takes out a rectangle). Undo and redo keep the selection. Everything below then works on just the selected cells. The Selection panel then offers:

  • Fill the active layer with the brush (or random mix); Clear the active layer; Clear everything (all layers and the objects standing there, Shift+Delete).
  • Copy (Ctrl+C) and Cut (Ctrl+X) take what you see: layers switched off in Layers, and roofs hidden by As if inside, stay where they are, so copying the inside of a building takes its floor and walls, not its roof. Straight after, the copied block follows the mouse to show where it would go: click to paste (Ctrl+V starts pasting again later). A message at the bottom says what was copied, and the Copied panel on the right shows it, with Paste again and Save as preset…. Esc stops pasting, closes the panel and deselects. Objects and NPCs in the selection come along, so Cut then Paste moves an area with everything in it — even the whole map.
  • Re-roll and Find & replace… (3.5).

Every copy of a tile. Double-click a tile to select every cell with that same tile on its layer (all the fence posts, say): Delete, Ctrl+C and Ctrl+X act on just those tiles. Switching view (Tiles, Objects, Walkability…) clears the selection.

One layer of a selection. After selecting an area, Shift+scroll narrows it to one layer at a time (Floor 1, Wall 1, …, then all layers again): only that layer's tiles stay highlighted, and Copy, Cut and Delete act on just them. For example, select 10×10 cells, scroll to Wall 1, and Delete removes only the Wall 1 tiles. Esc goes back to all layers; a second Esc deselects.

Which layer a tile goes on. With a tile ready to paint, Shift+scroll moves it to the next or previous layer of its kind; the preview under the cursor shows it in front of or behind the tile already at that spot (a wall on a lower layer is drawn behind the higher layers' tiles there).

What a paste replaces. While a paste or preset follows the mouse, the cells whose existing tiles it would replace are shaded red, and a note at the bottom counts them, before you click. Hold Alt when clicking to stack instead of replacing.

Empty cells paste as transparent. Hold Alt when you click to paste to stack the paste onto what's there (into the next free layer, adding layers as needed) instead of replacing it. Pasting into another map that doesn't load the copied tiles' DT1s offers to add them; if one of them has the same file name as a different DT1 the map already loads, it asks for a new name first (two libraries with one name get mixed up, placing the wrong tiles) and adds a renamed copy. Esc first drops what's on the cursor (a paste, an object, the paint tile), then deselects.

3.5Find & replace, re-roll

Find & replace (Ctrl+H, or Replace… on the ribbon) swaps every use of one tile for another, on every layer of the active kind or only the active layer, in the whole map or the selection. It starts with the selected cell's tile and your brush; Show them on the map marks every match. One step to undo.

Fill a selection with one tile: select an area with the Select tool, then click a tile in the Tiles panel: every selected cell gets it, on the active layer of its kind (floors on a floor layer, walls on a wall layer, shadows on the shadow layer), as one undo step. Deselect (Esc) first to paint with the tile instead.

Re-roll (Selection panel) mixes up the active layer inside the selection: each tile becomes a random tile of the same group (main index) already used there, so repeats are less visible. It never brings in tiles that weren't there.

3.6Undo and the History panel

Ctrl+Z undoes and Ctrl+Y redoes, without limit. The History panel lists every step by name (“Paint rectangle on Floor 1 (36 cells)”, “Paste 57×41 + 32 objects”…); click one to go back — or forward — to just after it. Map as opened undoes everything. Undoing back to the saved state counts as saved again.

3.7The Cell panel

Click a single cell with Select to edit everything in it. Each layer that has a tile is a card with the tile's picture and the DT1 it comes from (click the file name to show it in the Tiles panel). Every field has a ? that explains it:

  • Kind (orientation) on wall layers: left/right wall, corner, door, pillar/tree, roof, lower wall, special tile…
  • Main index and Sub index: the tile's number.
  • Present (prop1): 00 means empty.
  • Hidden in game: the game won't draw the tile.
  • Raw bytes: all four property bytes, to set every bit by hand.
  • Tag value on maps with a tag layer.

Empty layers are one line with Add (puts your brush tile there). × clears a layer. Warp tiles also show where they lead (chapter 6).

3.8Walkability: sub-tile flags

Painting walkability on the map (this map only). Switch to View → Walkability (W): the side panels make way for the Walkability panel and the map shows every sub-tile (5×5 per cell) that blocks walking (amber) or jumping and teleporting too (red). Choose Blocked or Walkable, what it blocks or allows (walking, jumping & teleport, sight & light, players only) and a brush (1×1, 3×3, 5×5 sub-tiles or a whole cell), then click or drag over the map. Shift+drag paints a rectangle and holding Ctrl does the opposite. Each stroke is one undo step; Done brings the other panels back.

It changes nothing for other maps. The game adds up the sub-tile flags of every tile in a cell, hidden tiles included, so blocking puts an invisible floor tile holding just those flags into a free floor layer of the cell (like Tal Rasha's tomb's own blockers), and making a sub-tile walkable that a tile blocks gives that cell its own copy of the tile without the flag (same picture and variants; a north-corner wall's other half comes along). Both go into a small tile library made for the map, <map>_walk.dt1 next to it, which is added to the map's tile libraries and level type. A cell whose two floor layers both hold real tiles has no room for a blocker; the panel says which cells it skipped.

Changing a tile everywhere. To change the flags of a tile itself, for every cell and map using it, use the Cell panel:

Every tile has 25 sub-tiles (a 5×5 grid over its floor diamond) whose flags decide where units can walk, see, shoot and teleport. Under each card, Sub-tile flags (walkability) shows them on the tile:

  1. Pick a flag (Block walk, Block light & sight, Block jump/teleport, Block player walk, Block missiles…). Hover a flag for what it does.
  2. Click or drag over sub-tiles to set it; start on one that has it to clear instead.
  3. Check the result on the map with Walkability (W).
  4. Save DT1s to mod in the bar at the top of the panel, or Discard.
Important The flags belong to the tile in its DT1: every cell and map using that tile changes. Change all variants (on by default) keeps the random variants of the tile alike.

3.9Resizing and new maps

Map → Resize shows handles on the four edges: drag them to add or remove cells (objects move with the cells). Resize… does it by numbers. When the map is a whole level of its own, saving it after a resize also sets that level's size in Levels.txt (SizeX/SizeY, all difficulties) to match: the game stops with an error building a level whose map isn't its size. Map → New map creates an empty map, 150×150 by default, with no tile libraries: the DT1 library opens straight after, to choose them from any act. A new map is shown in the Act 0 colours (only the colours that look the same in every act; magenta marks those that change between acts), so tiles from different acts look as they will in game; View → Colours switches palette, and a map remembers the one you pick. Its act is Act 5 by default, the act the game gives every level added with Add to game. It's saved where Save path says. Level type chooses where its tiles come from (hover the ? next to each): (New Lvltype) starts empty as above and gets a level type of its own when it's added to the game, listing just the tile libraries it uses; (Choose Existing) starts with an existing level type's tile libraries (from LvlTypes.txt) in that act's colours, and Add to game then starts from a level of that type. Use Game → Add to game to make the game load it; that also gives the map a level type of its own, holding just its tile libraries, when it needs one.

4Objects and NPCs ↑ Contents

4.1Placing from the gallery

  1. Switch to Objects (O, or Shift+O from a tile tool).
  2. In Objects & NPCs, filter by NPCs or Objects or type a name; every one is shown with its sprite.
  3. Click one, then click the map to place it. Keep clicking to place more; Esc stops.

The list is the act's placeable objects and NPCs, worked out from the game's own tables (and your mod's).

4.2Moving and editing objects

In object mode, drag an object to move it; Delete removes the selected one. Double-click an object to select every object of the same kind on the map (all 19 torches, say): Delete, Ctrl+C and Ctrl+X then act on all of them. Switching to another view deselects objects. Ctrl+C copies the selected object onto the cursor, shown in green; Ctrl+X cuts it, taking it off the map and showing it in red. Click the map to put it down (an NPC's path moves with it); Ctrl+V brings it back for another copy, and Esc drops it from the cursor. The name a player sees when pointing at an object comes from the game's string tables; a few objects (the guild objects Blizzard cut, such as Guild Vault and Steeg Stone) have none and show an empty box, which the Compatibility check finds and fixes by adding the names to your mod's patchstring.tbl. The Preview panel animates the selected object in every direction. The Object panel edits its type, id, position, flags and its NPC path (the points an NPC walks between).

4.3“In this map”: find any object

In this map lists everything placed, grouped by name with a count (Chicken ×4…). Type to search by name or id. Click a name to select it and centre the view on it; click again for the next one of that kind.

5Presets ↑ Contents

A preset is a reusable piece of map — a building, a wall run, a group of trees.

  • Save selection (Map → Presets, the Presets panel, or Save as preset… in the Copied panel after a copy) stores the selected area as a preset in your mod folder, so it travels with the mod. The Save as preset window asks for a name and a category (one of your saved presets' categories, or New category…), shows a picture of the preset, and lets you choose what it keeps: Floors, Walls, Roofs, Shadows, Markers (special tiles) and Objects & NPCs, each with how many there are. It starts from what you see: with As if inside on, Roofs starts unticked, so the inside of a building saves without its roof; with it off everything is ticked, and one click on Roofs leaves them out. Layers switched off in Layers start unticked too.
  • Suggest finds structures that recur across the maps sharing this map's tiles and offers them as presets.
  • Click a preset, then click the map to place it (like a paste; Alt stacks it onto existing tiles). Red cells show the tiles it would replace. Rest the pointer on a preset for an enlarged picture of it, with its size, category, objects and the tile libraries it uses.
  • Right-click a saved preset to place, rename, move it to another category, duplicate or delete it (a deleted preset's file is kept aside as a backup). Right-click a suggestion to place it or save it to the mod.
  • Sharing presets: Export all… (top of the panel), Export on a category heading, or Export… / Export category… in a preset's right-click menu saves them as a .zip with the tile libraries from your mod they use (the game's own DT1s are left out: everyone has them). Import… adds presets from such a file, or from a single preset .json: it shows what it will add first. A tile library already in your mod exactly is not written again; a different file under the same name is kept, and the imported one is saved under a new name that the imported presets use.
  • The Preset builder starts with this map's tile libraries; add any other DT1 with Add a DT1. Tiles from a library that isn't in the Act 0 colours yet (an added one, or one of the map's) are copied into the preset converted to Act 0, so a preset looks right in any act.

Open the panel with the Presets tab next to Tiles, or Map → Presets.

6Warps: connecting maps ↑ Contents

In Diablo II each map preset is its own level, and levels are joined by warps. A warp special tile with main index N (0–7) uses its level's link N: Levels.txt column VisN says which level it leads to, and WarpN which kind of warp it is (a LvlWarp.txt row: stairs, cave entrance…). DS1 Studio reads and edits these for you.

Seeing where a warp leads

  • On the map, warp markers read e.g. Warp · link 1 → Catacombs Level 1, or (not set) when the link is empty.
  • Select the warp cell: the Cell panel shows the level it leads to, the kind of warp, and Open buttons for that level's maps. Levels built at random by the game have no map to open.

Changing where it leads

  1. Select the warp tile and click Change where it leads… (or Connect it to a level…).
  2. Search and pick the level it should lead to, and the kind of warp.
  3. Tick also add the way back to give the target level a link back here (its map needs a warp tile with that link's number).
  4. Apply writes Levels.txt in your mod. Remove link clears it.
Note A map must be tied to a level before its warps lead anywhere: use Add to game first. If your mod ships compiled .bin tables, rebuild them afterwards (see 12.3).

7Importing DS1 and DT1 files ↑ Contents

Bring maps and tile libraries from anywhere on your computer into your mod, with the game's tables updated so they load without crashing. Both are in Home → File → Import ▾.

7.1Import DS1 (with its tile libraries)

  1. Import ▾ → Map… and pick the .ds1 file. It's checked first: a file the game couldn't read is refused. (A map package .zip from Export map can be picked here too: it opens the package import, tables included.)
  2. A .ds1 on its own brings none of its rows from the game's tables (Levels, LvlPrest, LvlTypes, CubeMain, AutoMap), so a warning says your own are used as they are: if they don't match the map and its tile libraries, the game can crash when it loads or while walking in it. Add it to the game afterwards and run the Compatibility check.
  3. Give the map a name (letters, digits, - and _). It will be saved as expansion/Map/<name>.ds1.
  4. Check Tile libraries this map uses: every DT1 the map names is ✓ in your game/mod, ＋ provided by a DT1 you picked, or ✗ missing.
  5. For missing ones, click Add DT1 files… or Add folders… (subfolders included). They're matched by file name, using the folders to tell same-named files apart; you can also choose a file for any library from its list.
  6. If the map names the same tiles twice in different folders (an original and a copy), a warning explains that the map would show a random mix of them; keep one copy of each (on by default) leaves out the first-listed copies. A picked DT1 with the same name as a library you already have can be chosen on that library's line to replace it.
  7. Import stays unavailable while any library is missing — find those DT1s, or tick import anyway (their tiles will show as missing and the game can't draw them).
  8. Import. The provided DT1s go into PD2assets/<folder>/ (keeping the paths the map names) and the map is pointed at them. With add it to the game next ticked, Add to game opens, pre-filled with a level that uses the same tiles — click Apply.

7.2The DT1 library: import, browse, build

Everything to do with tile libraries happens in one window: Home → File → Import ▾ → DT1s… or Map → DT1 library…. It lists every DT1 the game and your mod have; you can bring in your own, look through any of them, add whole libraries to the map, or build a custom DT1 from single tiles.

Bringing in DT1s from your computer:

  1. In the library window, + Add DT1 files… (one or several) or + Add a folder… (every .dt1 inside, subfolders included).
  2. Choose the folder under PD2assets/ they go into. Keep the folder structure keeps the picked folders' subfolders.
  3. Check the list: each file's tile count, unreadable files (left out), files that will be replaced (the old one is kept as .bak). Untick any you don't want.
  4. With a map open, add them to this map's tile libraries puts each in a free File slot of the map's level type and in its Dt1Mask, so the game loads them. The free slots are shown; a level type has 32.
  5. The library then shows the first one you brought in (under PD2assets/ in its tree).

From the game library

The window lists every tile library the game and your mods already have, by folder, with a search box (the map's own libraries first). Click one to see all its tiles, filtered by kind; rest the pointer on a tile to see it enlarged, click it for its details. The tiles are shown in the library's own act colours; Colours switches to the map's act, or to Act 0, which shows in magenta the colours that change between acts. Choose this library for each one you want, then Add to the map. Act 0 is the standard: with Convert them to Act 0 colours ticked (the default), each library that uses colours changing between acts is converted first, so its tiles look right in any act; a library from the game's archives gets its converted copy in your mod, which every map using it shares. The map's level type and Dt1Mask are updated as in Tile libraries. DT1 files you import (+ Add DT1 files…) are converted as they come in, and custom DT1s are built in Act 0 colours unless you untick it.

Building a custom DT1 from single tiles

Switch the window to Build a custom DT1 to put together a new tile library from single tiles of any others.

  1. Open a library and click tiles to tick them (Shift+click ticks a range, Tick all shown takes everything the filter shows). Go on in other libraries: the tree marks the ones you picked from, and Picked tiles collects them all (click one to go back to its library, × to drop it).
  2. Name it. Keep the name short, 12 characters or fewer is best, using only letters, digits and _: spaces, dots, dashes and accents can break the game's tables and archives. The whole path has to fit the game's 41-character limit for tile paths, so the window says how long it may be. It goes into PD2assets/custom/ unless you change the folder.
  3. Check the summary, then Create DT1 and add it to the map.

What the new library gets:

  • Each tile exactly as it was: pixels, walkability (sub-tile flags), sound, roof height and rarity are copied byte for byte.
  • Whole pieces: a north corner wall brings its other half, and an animated tile all its frames. Special tiles (markers) can't be picked.
  • Numbers that don't clash: the game finds a cell's tile by its orientation, main and sub index among every library the level loads. A tile whose number the level already uses, or another picked tile has, would be mixed with it at random, so it gets the first free number instead; the summary lists these. Tiles you pick that share a number in their own library stay together as variants.
  • The tables: the library goes into a free File slot of the map's level type and its Dt1Mask (a level type of its own if other levels share it, as in Tile libraries), and each tile's AutoMap.txt pieces are copied from the level it came from under its new number. Originals are kept as .bak.
Colours A DT1 stores palette numbers, not colours: in game its tiles take the colours of the level's act. Tiles from another act's library can look different there; Colours → this map's act shows them as the game will. Tick Make it act-safe (Act 0 colours) to fix that: every colour of the picked tiles is snapped to the nearest one that looks the same in every act (Gimli's Act 0 palette; nearest by plain RGB distance, as the community's Act 0 tile sets were made), judged by how it looks in the act its library was drawn for (its folder's: ACT1-ACT4, expansion = Act 5, Guild = Act 1; else the act its art fits best, worked out from the tiles; only failing that this map's). The window says how many picked tiles use act-specific colours, and the picked tiles show how they will look. Resting the pointer on a picked tile shows it enlarged.

8Tile libraries and the DT1 editor ↑ Contents

8.1Tile libraries

Map → Tile libraries reviews the DT1s the map is attached to. The list says, for each, how many of its tiles the map places (drawn from a later library when another library with the same tile numbers is the one the game draws) and whether it is the game's or your mod's. Click one to see its tiles: the ones the map uses are outlined in green with how many cells use them, and Used in this map shows only those. For a tile you click:

  • Show on map marks every cell that uses it.
  • Remove this tile from the DT1… rewrites the DT1 without it (the other tiles stay exactly as they were; the original is kept as .bak). You're told first if the map uses it, or if other level types load the DT1 too.

Rename… renames a DT1 in its folder (letters, digits and _): the file is written under the new name, every level type that loads it (LvlTypes.txt) and the map are pointed at it, and the old file is moved aside to .bak, never deleted. The × next to a library takes it off this map (Remove from the map); the file stays. + Add libraries… opens the DT1 library. Removing tiles and renaming work on your mod's own DT1s only: one in the game's archives is shared by every map, so make your own copy with the DT1 editor first.

DS1 Studio keeps the game in step: new DT1s go into free File slots of the level type (LvlTypes.txt) and the map's Dt1Mask (LvlPrest.txt) is recomputed. When two loaded DT1s have the same tile, the one listed later replaces it, as in the game.

8.2The DT1 editor

Map → DT1 editor edits a copy of any DT1: choose it in the tree on the left (every library in the game and mod, by folder), select tiles (Shift+click for a range, or From preset / From map selection), and edit their colours (8.3), pixels (8.4) or settings (8.5). Clicking a tile opens it in a zoom window you can move, resize and zoom to single pixels. Save writes a copy under a new name, or overwrites the original, and can switch your map over to it with the tables updated.

Palette Editing uses the Act 0 palette: only the 225 colours that look the same in every act, so edited tiles work in any act. Tick highlight colours that change between acts to see act-specific pixels in magenta; Make act-safe converts them.

Make act-safe: fixing odd red or purple tiles

About 30 of the palette's colours change between acts, so tiles drawn for one act (say Act 1) can show red or purple patches in a map of another act, here and in game. Map → Make act-safe lists every DT1 the map uses, how many of its pixels use act-specific colours, and a now / after preview. For each DT1, choose the act it was drawn for so the after preview looks right, then click Convert. Every DT1 that still uses such colours is ticked, since Act 0 is the standard. The DT1s are saved into your mod with .bak copies, and every map using them gets the new colours.

Random red cells? If only some cells show the odd colours, in a random scatter, the map probably loads two copies of the same tiles: an original and an act-safe copy, often from an import. The game picks among both copies' variants at random. Make act-safe and the Compatibility check both detect this (“tile libraries loaded twice”) and remove the extra copy from the map's libraries, so no DT1 needs converting.

8.3Recolouring

Hue, saturation, brightness, tint, and replace a colour — for the whole file, the selected tiles, a preset's tiles, or the tiles in your map selection. The preview is exact.

8.4Pixel painting

Double-click a tile (or Paint pixels…) to paint it pixel by pixel. Only the tile's real pixels can be painted.

9Game data ↑ Contents

9.1Data tables

Browse and edit any .txt table of the game in a spreadsheet view. Column headers have a ? explaining what the column does. The shortcuts (LvlPrest, LvlTypes, Levels, Objects, MonPreset, CubeMain) jump to the open map's row where there is one. Saving writes the table into your mod.

9.2Add to game

Makes the game load the open map. The dialog lists every field it will write, with the old value, the new value and the reason, before you click Apply. There are two ways to add a map:

  • A new level, with settings (monsters, lighting, sound, tile set) copied from a level you choose. A Levels.txt row is added as the next record, and its LvlPrest.txt row points at the map. Level type chooses between a new level type (a LvlTypes.txt row of its own, listing just the map's tile libraries) and the one it copies from (a new one is still made if that type lacks libraries the map uses and other levels share it). A map made with (New Lvltype) in New map starts with the first ticked.
  • Replace the map of an existing preset level. The level's own LvlPrest row is pointed at the map. Only preset levels can do this: levels the game builds at random don't load a single map.
Automap layer A new level keeps the Layer of the level it copies (PD2's maps all share 98). The game takes layers up to 100: a level with a higher one crashes the game the moment a player enters it (earlier versions of DS1 Studio counted up past it). The Compatibility check reports such a level and sets it back.

Either way, the tile libraries the map uses go into free File slots of the level type (LvlTypes.txt), and the preset's Dt1Mask selects them. The rules it follows come from the game's own code and tables:

The Compatibility check checks the same rules for any map already in the game, and offers one-click fixes: rows out of order (put back in Id order; no Id changes), a preset pointing at a missing level, the level size, act, palette, an overlapping position, the file count and a copied quest requirement. A new level has no connections yet: link it with warps or open it with a cube recipe. Set the DS1 header to Act 5 (the check offers it), so the map's object numbers are read as Act 5 objects.

Changing a level's level type

Game → Level type… gives the map's level another level type (Levels.txt LevelType): the LvlTypes.txt row that lists the tile libraries the level can load, and whose AutoMap.txt pieces it draws. Pick the new type from the list; the dialog lists every change before anything is written, then the map reopens with its new type and the Compatibility check runs. What it does, following the game's own code:

  • The new type lists every tile library the map uses (free File slots are filled from File 1, without gaps), and the map's Dt1Mask selects exactly those slots.
  • A type other levels use keeps its tile list for them: if it lacks some of the map's libraries, the level gets a copy of it of its own (you can also ask for a copy). The copy keeps the Act of the type it copies; a level can use a type of another act, as the game's own Pandemonium levels and PD2's map levels do.
  • When the map's LvlPrest row lists several maps (the game picks one, like the town's variants), every library the row loads stays loaded, so the other maps keep their tiles.
  • AutoMap.txt: a copy gets the chosen type's rows under its own number (in mods that read level-type numbers, like PD2; the unmodded game only knows its 36 types by name), and the tile kinds the map uses that the new type has no piece for take the old type's pieces.
  • Only levels built from one map (preset levels) can change type: the game builds maze and outdoor levels from pieces it chooses by level-type number. A map that belongs to several levels asks which one.

9.3Cube recipe

Creates a new item and a Horadric Cube recipe that makes it. Pick the template item and the ingredients from lists with icons, or type your own item code (checked against the game's items). DS1 Studio takes care of the rules that otherwise crash or break the game:

  • Placement: the new item is added at the end of Misc.txt. Items are numbered by their position, so one inserted in the middle renumbers every item after it.
  • No duplicate recipes: a recipe with the same ingredients as an existing one is refused. The cube only runs the first match, so the new one would never work.
  • Never a random drop: the new item gets spawnable 0, and references to the template's code (normcode…) are changed to the new code.
  • Safe templates only: elixirs aren't offered; a copy of one crashed the game when hovered. Items of a type the base game doesn't have, like PD2's maps, need a tick first. The mod's own code handles those types and only knows the mod's own item codes.

A map item that opens this map

Pick one of your mod's map items as the template; they are listed first under Map items (open a level). The new item then opens the map you have open, and DS1 Studio makes every change for it:

  • Misc.txt: the map item, with len set to the map's level number. PD2's map items open the level named in len: "Halls of Torture Map" has len 193, which is level 193.
  • patchstring.tbl (data/local/lng/eng): the item's name, and optionally the level's name as shown in game. Every existing string keeps its number.
  • Levels.txt: the level's LevelName/LevelWarp point at that name, if you name the level.
  • CubeMain.txt: the recipe, made the way your mod's other map recipes make their maps (e.g. ,nor, lvl, ilvl).

The map must be a level in the game first. If it isn't, the dialog offers Add to game. After creating it, rebuild the .bin tables (-direct -txt) if your mod uses them.

Recipes and items DS1 Studio made are listed under Made by DS1 Studio in the dialog, where you can remove them: one at a time, or tick several (Select all ticks every one) and click Remove selected. You are asked to confirm first, and the dialog stays open afterwards. Remove an item only when no character holds it: a character with an item whose code is gone may not load; an item can be removed together with the recipes that make it.

9.4Compatibility check

Checks the map will load and play in game: missing tiles and DT1s, table wiring, DT1s used but not loaded by the level type, entry markers, a missing waypoint, NPCs on unwalkable ground, stacked objects, walls missing from the automap, compiled .bin reminders. Most results offer one-click fixes, and Show on map marks the cells involved. Map edits made by fixes can be undone.

Ways out. A warp tile whose link has no level in Levels.txt leads nowhere; the fix opens the warp link editor for it. A level built from this map alone, with no working warp and no waypoint, can only be left by town portal (a player without a scroll or tome is stuck): Add an exit warp… opens the link editor with the act's town chosen, then gives you the warp tile to click where players should leave. Pick a Kind of warp that suits the map before applying. If leaving by town portal is what you want, ignore the warning.

Intended warnings. When a warning is what you want (a level left only by town portal, a level type shared on purpose…), click Accept as intended under it: it leaves the check and its counts for this map, and later checks (including the automatic ones after saving) don't count it. Accepted (N) at the top shows those warnings with their full text and fix buttons; Un-accept puts one back.

Tile libraries loaded twice. Two DT1s with the same tile numbers (an original and a copy, often from an import) make the game pick between them at random on every cell: a few cells show the other copy, sometimes in odd colours. Compare the copies and choose… shows the same tiles from each side by side; keep the one that looks right and the other leaves the map (and its level's Dt1Mask).

Tile paths too long. The game holds at most 41 characters of a tile path after data\global\tiles\; a longer one can crash it. The check lists every such path the level uses, and Rename… opens them together: give each a shorter path (a counter shows how many characters are left) and DS1 Studio moves the files, updates every LvlTypes.txt and LvlPrest.txt row that names them, and keeps the old files and tables as backups.

AutoMap rows with no picture. A rule whose Cel1 is −1 stops the game while it loads AutoMap.txt (earlier versions of Clear piece wrote them). The check finds them and removes them in one click, backing AutoMap.txt up first.

Colours. Tile libraries the level loads that weren't drawn for its act and use colours that change between acts are listed, with how much of each; Convert them to Act 0 colours fixes them in your mod (originals kept as .bak). If the map came from someone working with an Act 0 tile pack (such as Gimli's), their copies of those files are the exact match.

Tiles with no graphic. The check names the tile libraries the map itself lists. If you have them all and tiles are still missing, your copies differ from the ones it was made with (edited versions, or an Act 0 pack): ask the maker for their files. Adding another library that happens to use the same tile numbers, or clearing the cells, loses the maker's tiles.

Maps from someone not using DS1 Studio A map is usually sent as the DS1, the DT1s the maker changed, and rows of their AutoMap.txt. Three things differ between mods: the DT1s they didn't send (their copies may be Act 0 or edited: the check above tells), the level-type numbers in their AutoMap rows (use Import → AutoMap rows…: it lists each LevelName in the file and adds the rows under the level type you choose, the open map's by default, skipping rows already there), and files that already exist in your mod (the DT1 import names the levels that load a file it would replace). When a map import finds two picked files with the same name, the one in a spare folder (og/, old/, backup/…) is never used over the real one.

9.5The automap

View → Automap (A) shows the in-game automap over the map. Walls outlined (pink unless you change it) have no AutoMap.txt entry: a hole in the automap. Floors without one are normal (the game draws few floors). Click a cell to see the automap piece of each of its tiles: Change piece… picks another (No piece, first in the list, leaves those tiles off the automap), and Clear piece takes the tile off the automap straight away. Both work on Only this cell by default: the cell gets a tile of its own (a copy under a new tile number), so the rest of the level keeps its pieces; choose the wider scope to change every tile of that kind (style and sequence) on the level instead. Clearing removes the matching AutoMap.txt rows (a row with Cel1 −1 crashes the game while it loads, so DS1 Studio never writes one and refuses to save a table that has one); a cleared tile has no entry, so it is outlined like any tile without a piece. Where a tree or roof stands in a wall’s place, the cell has no wall tile and so no wall piece: the cell panel offers choose a wall piece… to draw one there anyway.

Look (in the Automap panel, and Look on the editor's preview) decides how it is drawn, and is remembered:

  • Pieces show in their own MaxiMap.dc6 colours, as in game. (Colouring each kind of piece its own way is switched off for now.)
  • Each kind can be shown or hidden, with how many pieces of it there are.
  • Opacity, Thickness (as thin as in game, or thicker to see at any zoom) and Map under it (how much the map underneath shows).
  • Outline walls with no entry, in a colour of your choice. reset look goes back to the defaults.

The floating legend on the map follows the look. Game → Automap editor (or Open automap editor… in the panel) sorts the map's tiles into categories: Walls, Walkable floors, Water, Roofs, Objects & trees and Shadows. Click a category and all its tiles light up on the preview; the right side then sets its Look (opacity, show) and its Texture, the automap piece the game draws. A selected category opens into its parts: Walls into Left walls, Right walls, Corners, Doors, Wall ends and Lower walls; Objects into Trees and Columns & props. Each part shows its tile count, what is missing and the piece it draws now. Click one and the right side works on that part alone: its Look (opacity, show) gives it a look of its own (Use the walls look again undoes it), and every automap piece is shown below, the ones used for that kind of tile framed and first, to replace just that part's piece (corners keep one piece per corner shape). Pieces are shown in their own MaxiMap.dc6 colours, as the game draws them; AutoMap.txt has no colour column. Walls without an entry are missing (holes); other tiles without one are simply not drawn. Apply sets the chosen pieces, Suggest for the N missing wall kinds fills the holes with the pieces the level uses for look-alike tiles, and Pieces as in takes a whole wall set from another level. The Map ↔ Automap slider over the preview fades between the map and its automap. Nothing is written until you Save to AutoMap.txt; tile kinds one by one still lists every kind for fine edits.

Draw all the same… (above the list) gives a whole kind of tile the same pieces in one go:

  • Walls: every wall shape (left and right walls, corners, doors, wall ends, lower walls) gets its own piece, so each still faces the right way, all taken from one wall set — Pieces as in any level (this one by default). Click a shape to pick another piece for it.
  • Floors: one piece for every floor, or leave them all off the automap (as most of the game's levels do).
  • Water: Find the water tiles picks out the floors nobody can walk on that are dark or bluish (rivers and lakes; lava and blocked ground are left out), shows them to untick any that aren't water, and gives them one piece — the level's own water piece to start with.
  • Objects & trees: one piece each for trees and for columns/props, or left off.
  • Only kinds without an entry fills the gaps and keeps the rest as it is.

The result goes into the changes shown on the preview; Save to AutoMap.txt writes it.

10Sharing and exporting ↑ Contents

10.1Map packages

Export ▾ → Map package… (Home → File) puts the DS1, its DT1s, any modded object sprites and every table row the map needs into one .zip: its LvlPrest, Levels and LvlTypes rows, the CubeMain recipe made for it (with its Misc.txt item), the AutoMap rows of its level type, and LvlWarp/LvlMaze rows. The dialog lists the five main tables with how many rows each gives, and warns about any the map has none in (not added to the game yet, no cube recipe, no automap pieces). DS1 only… saves just the map file.

Import ▾ → Map… with a .zip merges such a zip into your mod safely: same-named rows are reused, clashing ids get new numbers (AutoMap rows follow a renumbered level type), DT1s go into free slots and the Dt1Mask is recomputed; AutoMap rows already there aren't added twice. Importing the same map twice changes nothing. The import lists which of the five tables came with the map and warns about missing ones: your own rows are used for those, and the game can crash if they don't match the map.

The maker's cube recipe and map item aren't copied: their item code, the level number the item opens and its name only fit the maker's tables. Instead, with make a cube recipe and map item for it next (on by default), the imported map opens and the Cube recipe tool starts with the maker's ingredients and item name. Create makes an item with a free code that opens the map's level number in your tables, names it and the level, and refuses a recipe your mod already uses: enter a game, cube it, and use the portal.

For a developer adding the map by hand

A developer who doesn't use DS1 Studio can add the map with a text editor: every package has a for-developers folder with

  • README.txt: for each table, which lines of the maker's table are the map's (e.g. Levels.txt line 214, Id 212), where they go in your own table, and which numbers link the tables, so they can be renumbered safely. Levels, LvlPrest and LvlTypes are read by row position, so their rows are always appended with the next Id/Def; the README says what else to change when an Id changes (LvlPrest LevelId, LevelType, Misc len…).
  • full/: the maker's tables exactly as they are, to look the lines up or compare.
  • rows/: just the map's rows of each table under its header line, ready to paste.
  • strings.txt: the names the map uses and their text.

DS1 Studio's own import leaves that folder alone.

10.2Export image

Saves the whole map or the selection as a PNG at 100%, 50%, 25% or 12.5%, with or without objects, drawn with the layers currently shown. Sizes too large for one image are greyed out. Colour adds the Walkable or Spawns overview (2.4) with its legend; it starts on the one shown on the map.

Copy view (Print Screen)

View → Copy view (also Home → File → Export ▾), or the Print Screen key, copies the map pane exactly as it is on screen (zoom, overlays, selection, minimap) as a picture: paste it anywhere with Ctrl+V, into a chat, a document or an image editor. Windows 11 opens its own Snipping Tool on Print Screen unless Settings → Accessibility → Keyboard → Use the Print screen key to open screen capture is off; either use the button, turn that off, or give Copy view another key in Keyboard shortcuts.

10.3Export .ds1

Export map → DS1 only… saves a copy of just the map file anywhere on your computer, without touching your mod. It carries no tile libraries or table rows: to hand a map to someone, export the package.

12Safety and troubleshooting ↑ Contents

Before you start DS1 Studio is in beta. Keep a backup of your mod (and your game files) before editing.

12.1What DS1 Studio writes

  • Only into your mod folder: maps, DT1s, .txt tables, presets. Your Diablo II install is only ever read.
  • A file it replaces is kept as <name>.bak the first time, so the original survives.
  • Autosaved copies live in the app's own storage, not in your folders (1.6).

12.2If something goes wrong

If part of the app fails, it shows what happened instead of a blank window, with Try again, Close this map, Report this bug (pre-filled with the error details) and Reload DS1 Studio. Your unsaved changes are kept in the autosave.

When the game crashes

Diablo II writes every crash to a log in its folder (D2<date>.txt). Game → Crash log reads the newest crashes from your game and mod folders and says, in plain words, what they mean and what to do: a missing loading-screen image (EntryFile), a level placed too far out for the automap, AutoMap 1 on a level that isn't a town, a damaged .tbl, or a tile library, map or sprite the game couldn't open just before. The same crash repeated is shown once with a count. When the latest crash is one a map can cause, Run compatibility check finds and fixes it. Crashes it doesn't recognise are shown with where they happened, for reporting.

12.3Compiled .bin tables

The game reads compiled .bin copies of the .txt tables. After changing tables (Add to game, warps, tile libraries, cube recipes…), start the game once with -direct -txt so it rebuilds them, if your mod ships .bin files.

BGlossary ↑ Contents

DS1A map preset: a grid of cells with floor, wall, shadow and tag layers, plus objects and NPCs. The game builds levels from them.
DT1A tile library: the pictures and settings of the tiles DS1 cells refer to (chapter 8).
CellOne diamond of the map grid; each layer holds at most one tile in it.
Main / sub indexA tile's number. A cell asks for “kind + main + sub” and the game draws the DT1 tile with those numbers.
Orientation (kind)What a tile is: floor, left/right wall, corner, door, pillar/tree, roof, shadow, lower wall, special tile.
Variant / raritySeveral tiles can share a number; the game picks one at random, weighted by rarity. Animated tiles use it as their frame number.
Sub-tile flagsThe 5×5 walkability grid of a tile: block walk, sight, missiles, teleport… (3.8).
Special tileAn invisible marker: warps, entries, corpse and portal spots (2.7).
LevelA row of Levels.txt: one area of the game (a town, a dungeon floor), built from DS1 presets or at random.
LvlPrest.txtLists the DS1 files, the level each belongs to, and its Dt1Mask.
LvlTypes.txtLevel types: up to 32 DT1 File slots each.
Dt1MaskWhich of its level type's DT1 slots a DS1 loads (one bit per slot).
Warp / linkHow levels connect: Levels.txt Vis0–7 (target level) and Warp0–7 (LvlWarp row) (chapter 6).
Preset (DS1 Studio)A saved piece of map you can place again (chapter 5). Not to be confused with a DS1 “map preset”.
Act 0 paletteThe colours that look the same in every act (8.2).
Mod folderYour mod's folder; everything DS1 Studio saves goes here (1.5).
